## Problem

When a functional change skips the README, a new doc is left unlinked, or the
same fact is copied into several files, the documentation contradicts itself and
readers cannot tell which copy is current.

## Solution

Treat the docs as a single source of truth: every fact lives in one place, and
every place is reachable. Drift happens when a change updates behavior but not
its documentation, or when a fact is copied and the copies fall out of step.

1. Ship doc updates in the PR that makes them true. A functional change that
   touches setup steps, environment requirements, or file references leaves the
   README wrong the moment it merges, and a follow-up PR to fix it often never
   comes.
1. Link a new doc from the root entry point when you add it. An unreachable file
   is invisible, so readers fall back on a stale copy or ask a question the doc
   already answers.
1. Keep each fact (a procedure, template, or configuration step) in exactly one
   file and reference it from elsewhere. Copies drift apart, and a reader cannot
   tell which one is current.
1. For a fact another system owns (bot commands, third-party APIs), link that
   system's canonical documentation instead of restating the details. External
   details change without notice, so a local copy goes stale silently; for
   example, [DEV-140](./DEV-140.md) links the Wizard command docs rather than
   hardcoding a command string.

### Acceptance Criteria

- [ ] Functional changes update the README in the same PR
- [ ] New docs are linked from the root entry point, not orphaned
- [ ] No piece of information is duplicated across files
- [ ] Facts owned by another system link its canonical docs, not a restated copy
