## Problem

When a functional change skips the README, a new doc is left unlinked, or the
same fact is copied into several files, the documentation contradicts itself and
readers cannot tell which copy is current.

## Solution

Keep documentation coherent with every change.

1. When a change is functional, update the README in the same PR. If it affects
   setup steps, environment requirements, or file references, the README must
   stay in sync.
1. When adding a documentation file, make it reachable by interlinking from the
   root entry point. Do not create orphaned files.
1. Keep each piece of information (procedures, templates, configuration steps)
   in exactly one place. Reference it from other docs rather than copying it.

### Acceptance Criteria

- [ ] Functional changes update the README in the same PR
- [ ] New docs are linked from the root entry point, not orphaned
- [ ] No piece of information is duplicated across files
