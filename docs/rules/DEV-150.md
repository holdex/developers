## Problem

Once the goal is clear, the barriers to it are often left unlisted, or written
as solution technicalities like "missing library". Stakeholders cannot see which
user problems actually block the goal.

## Solution

Before writing any Problem issue, list the barriers that block the goal, framed
as business problems.

1. Derive the list only after the Spec is clear and agreed, per
   [DEV-130](./DEV-130.md).
1. State each barrier as a problem a user or the business faces, not a technical
   gap in the solution.
1. Keep each one understandable to a non-technical sponsor or stakeholder.

### Acceptance Criteria

- [ ] The barriers blocking the goal are listed before Problem issues are opened
- [ ] Each is a user or business problem, not a solution technicality
- [ ] A non-technical stakeholder can understand each one
