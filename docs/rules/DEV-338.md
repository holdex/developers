## Problem

A root README that omits what the repository is, where its docs are, or how to
run and deploy it forces every newcomer to reverse-engineer the project from
source. The one page everyone opens first fails them.

## Solution

The root README is the first and most-read page in the repository, so it must
answer, in order, what the project is, where to learn more, and how to run it in
every environment.

1. Open with an H1 title and a short description of what the repository is and
   does, so a newcomer understands it in one read.
1. Link the documentation index (`docs/README.md`), the README's one
   documentation child, so it is the entry point into the tree, per
   [DEV-337](./DEV-337.md). The index leads to the contributing guide and
   everything else, so the root need not link them directly.
1. Include a Setup section covering every environment the project runs in, each
   as its own subsection: Local (run it on your machine), Stage or Preview
   (deploy for internal demo and review), and Production (deploy for real use).
   Where an environment does not apply, say so and why, rather than omitting it.
1. Keep the commands and steps truthful and current. A README that lies about
   how to run the project is worse than one that says nothing.
1. Verify the README before pushing with `npm run check:rules`, which checks the
   title, description, docs-index link, and Setup subsections. The pre-push hook
   runs the same audit and blocks a push that fails it.

### Acceptance Criteria

- [ ] The README opens with an H1 title and a description of what the repository
  is
- [ ] It links the documentation index (`docs/README.md`)
- [ ] Its Setup section has Local, Stage or Preview, and Production subsections
- [ ] Environments that do not apply are stated as such, not omitted
