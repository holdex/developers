## Problem

A change that patches only the lines it needs leaves each file a little harder
to read, and an agent working in tangled code makes more mistakes on the next
change.

## Solution

Direct the agent to restructure every file the change touches, in the same stack
as the change. Agents structure code well, and well-structured code is what
keeps the next agent's error rate down.

1. Ask the agent to restructure the files the change touched, not only the lines
   it needed.
1. Keep behavior the same in the restructured parts; the tests that passed
   before still pass.
1. Put the refactor in its own `refactor(scope)` PR, stacked on top of the
   implementation PR per [DEV-325](./DEV-325.md). Keep it out of the
   implementation PR, so each diff shows either new behavior or new structure.
1. Refactor inside the implementation PR only when the change cannot be made
   without it, and say so in the PR description.

### Acceptance Criteria

- [ ] Files a change touches are restructured, not only patched
- [ ] The refactor keeps behavior the same, and existing tests still pass
- [ ] The refactor is its own PR, stacked on top of the implementation PR
- [ ] A refactor inside an implementation PR is explained in its description
