## Problem

A change that patches only the lines it needs leaves each file a little harder
to read, and an agent working in tangled code makes more mistakes on the next
change.

## Solution

Direct the agent to restructure every file the change touches, as part of the
change. Agents structure code well, and well-structured code is what keeps the
next agent's error rate down.

1. Include restructuring the touched files in the prompt, not only the lines the
   change needs.
1. Keep behavior the same in the restructured parts; the tests that passed
   before still pass.
1. Keep the refactor in the same stack. A small one rides inside the feature PR;
   a large one goes in its own `refactor(scope)` PR at the bottom of the stack,
   per [DEV-325](./DEV-325.md).

### Acceptance Criteria

- [ ] Files a change touches are restructured, not only patched
- [ ] The refactor keeps behavior the same, and existing tests still pass
- [ ] A large refactor is its own PR at the bottom of the same stack
