## Problem

When one comment carries several unrelated points, none of them can be resolved
until the last is settled, and a point nobody answered is lost among the ones
that were.

## Solution

A thread is the unit that gets answered, agreed and resolved per
[DEV-460](./DEV-460.md). Points mixed in one thread share its fate: the whole
thread stays open while any one of them is still under discussion, and the
answer to one point hides the silence on another. Give each point its own thread
so it can close on its own.

1. Put each point that stands on its own in a separate inline comment, on the
   line it concerns. Where no single line fits, use the heading of the section
   it concerns.
1. When a new point comes up while you reply in a thread, open a new inline
   comment for it instead of adding it to the reply.
1. For wording alone, use "Suggest changes" on the line so the author can apply
   it directly.

This applies to the author and the reviewer alike, and to every PR, including a
Spec under negotiation.

Bad, one comment on the PR:

> The approver picker should also list the CEO, the Workspace form needs the
> registered address, and removed drafts should stay visible to Compliance.

Good, three inline comments:

- on the approver picker line: "The picker should also list the CEO."
- on the Workspace line: "The Workspace form needs the registered address."
- on the removing a draft line: "Removed drafts should stay visible to
  Compliance."

### Acceptance Criteria

- [ ] Each inline comment carries one point that can be settled on its own
- [ ] Each comment sits on the line or section it concerns
- [ ] A point raised while replying in a thread has its own thread
- [ ] Feedback that only changes wording is posted as a suggested change
