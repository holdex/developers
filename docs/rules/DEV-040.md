## Problem

When a rule points at another by loose description, or uses a link style the
repo's linter rejects, the dependency is untraceable and the change fails on
push. A rule that names its neighbor inconsistently cannot be followed back.

## Solution

Make every rule-to-rule reference explicit and lint-clean.

1. Reference another rule by its ID as a link, so dependencies are traceable
   both in prose and in `depends_on`.
1. For issue and PR references, use the list-item format from the contributing
   rules, so GitHub expands them.
1. Link style is governed by each repo's own `rumdl` config, not by this rule.
   Some repos require reference-style links and reject inline ones. Run the
   repo's markdown lint before pushing rather than assuming a style.

### Acceptance Criteria

- [ ] Related rules are referenced by ID as links
- [ ] Issue and PR references use the list-item format
- [ ] `rumdl check` passes on the changed files before pushing
