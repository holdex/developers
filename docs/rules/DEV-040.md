## Problem

When a rule points at another by loose description, the dependency is
untraceable. And when the reference is plain text, or a link whose target is
wrong or missing, a reader cannot click through to the rule it names.

## Solution

When a rule refers to another rule, make the reference explicit and followable.

1. Name the other rule by its ID.
1. Make the ID a link whose target is that rule's file, so a reader can click
   through to it.
1. Where the referenced rule is a dependency, list its ID in `depends_on` too,
   so prose and metadata stay in sync.
1. Run the repo's markdown lint before pushing, so a broken or missing link is
   caught. Link style, inline or reference, is governed by each repo's own
   `rumdl` config, not by this rule.

### Acceptance Criteria

- [ ] Every rule-to-rule reference names the other rule by its ID
- [ ] The ID is a link that resolves to that rule's file
- [ ] A referenced dependency also appears in `depends_on`
- [ ] Lint passes with no broken or missing links
