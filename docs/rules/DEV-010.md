## Enforce One Behavior Per Rule File

### Problem

A rule that bundles several behaviors, or one behavior spread across several
files, cannot be checked or referenced cleanly. A reviewer cannot say whether a
subject passes it, and other rules cannot depend on a precise, single thing.

### Solution

Keep exactly one enforceable behavior per rule file.

1. State a single behavior that can be checked against one subject (a partner, a
   lead, a document, a PR).
1. If a rule needs the word "and" to join two unrelated behaviors, split it into
   two rules.
1. If one behavior only makes sense alongside another, keep them separate and
   link them with `depends_on` rather than merging.

#### Acceptance Criteria

- [ ] The rule describes exactly one behavior
- [ ] The behavior can be checked pass or fail against a single subject
- [ ] No unrelated behavior shares the file
